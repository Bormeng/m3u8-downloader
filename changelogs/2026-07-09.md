# 2026-07-09

## 新增:启动时检查 N_m3u8DL-RE 新版 + 主界面 banner

### 背景
N_m3u8DL-RE 项目持续在更新(v0.6.0-beta 后还会有新 release),但当前
App 没有任何机制感知新版本 —— 用户只能靠自己去刷 GitHub。

### 改动
- 新增 `UpdateChecker.swift`(`@MainActor` ObservableObject 单例):
  - 启动时通过 GitHub Releases API 拉最新 release 元数据
  - 24h 本地缓存(写入 UserDefaults)避免每次冷启动都打 API
  - 版本对比:本地读 `N_m3u8DL-RE --version` 输出,GitHub 读 `tag_name`,
    归一化(去 `v` 前缀、去 `+<sha>` build suffix、去 `-beta` 等
    prerelease 后缀)后比较
  - 默认开启启动自动检查,可在 Settings 关闭 / 手动"立即检查"
  - 不自动下载 / 不自动替换 binary —— 那些踩 codesign 和运行时
    文件锁,留给用户手动去 GitHub 拉
- 新增 `UpdateCheckerSettingsSection`:在 Settings(⌘, 里)显示
  当前版本、最新版本、发布时间、"在 GitHub 查看"链接、启动
  自动检查开关、立即检查按钮
- 新增 `UpdateBanner`:在主界面顶部(BrowserView 之上)显示橙色
  banner,提示有新版可用,带"在 GitHub 查看"链接和"关闭"按钮;
  关闭只是本次 session 不显示,下次冷启动仍会重新查
- `ContentView.task` 在首次出现时 fire-and-forget 调用 `check()`,
  检查器自己有 re-entrancy guard 和缓存,SwiftUI 重跑 .task 不会
  重复打 API
- 公开 API:`api.github.com/repos/nilaoda/N_m3u8DL-RE/releases/latest`、
  User-Agent `m3u8-downloader (nilaoda/N_m3u8DL-RE)`、超时 10s

### 影响范围
- 启动时会多一次 GitHub API 请求(被 24h 缓存兜底,不会变成
  "每次冷启动都打")
- 离线 / 网络抖动 / GitHub 限流都不会弹窗,只在 Settings 里留一行
  error log,主界面无感
- banner 不持久化"已忽略" —— 今天忽略不代表明天的新版也忽略

### 副作用 / 已知保留
- 当前 binary `0.6.0+df70f0b3...` 与 GitHub `v0.6.0-beta`
  归一化后都是 `0.6.0`,**本次冷启动不会显示 banner**(符合预期,
  binary 已经是同 release 的产物)。等下一个 release 发布后会
  自动出现
- 不在范围内:N_m3u8DL-RE 二进制本身的更新流(用户手动
  拉 binary 替换 `~/Movies/N_m3u8DL-RE` 后跑 `bin/deploy_app.sh`
  重新打包)
