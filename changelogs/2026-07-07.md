## 单一码率时也能看到真实分辨率 (1920x1080 / fps)

- 背景:之前只对 master playlist(带 `#EXT-X-STREAM-INF`)能正确显示分辨率和码率;
  抓到直接是 media playlist 的链接时,variant 列表只剩「Media · 单一码率」,
  用户没法判断这条流到底是多少 P。
- 改动:
  - `HLSProbe.swift` 新增 `probeMediaTrack(urlString:headers:timeout:)`,用
    `AVURLAsset` 异步加载轨道,从 `AVAssetTrack.naturalSize` /
    `nominalFrameRate` / `estimatedDataRate` / `formatDescriptions` 拿真实
    分辨率、帧率、估算码率和 codec。轮询 `tracks` key,15s 超时,
    用 `AVURLAssetHTTPHeaderFieldsKey` 带上 Referer 等 headers。
  - `BrowserViewModel.probeOne`:当解析结果只有 1 个 variant 且
    `resolution == nil` 时(就是 media playlist),调用上面的探针把
    resolution / frameRate / bandwidth / codecs 写回 variant。
    `statusMessage` 也从「单一码率」升级成「Media · 1920x1080 · 30fps」。
  - `M3U8Variant.displayLabel` 加上 `frameRate` 分支,列表里变体名也带
    fps 信息(master playlist 的 fps 字段之前没用到,顺便启用)。
- 影响范围:master playlist 行为不变(原路径已经能拿到 RESOLUTION)。
  仅在「单一码率」场景额外触发一次 AVFoundation 探测,失败时静默回退到
  旧文案,不影响下载。

## v2:绕开 AVURLAsset 对 m3u8 的处理,改用 URLSession + 本地 segment

- 背景:v1 的 `AVURLAsset` + `AVURLAssetHTTPHeaderFieldsKey` 在 macOS 14
  SDK 上拿不到轨道(老 `statusOfValue` 轮询立刻报 `.loaded`、
  `loadTracks` 拿不到数据),实测在 `huawei-baidu-alibaba.henxihuan-ma.top`
  这种 CDN 上始终 fallback。
- 改动:`probeMediaTrack` 重写。流程:
  1. URLSession 下 m3u8 playlist(带 Referer 等 headers)
  2. 解析出第一个 segment 文件名(如 `index0.ts`)
  3. URLSession 把 segment 下载到 `tmp/m3u8probe-<UUID>.ts`(同样带 headers)
  4. `AVURLAsset(url: 本地文件).loadTracks(withMediaType: .video)` 拿轨道
  5. 从 `naturalSize` / `nominalFrameRate` / `estimatedDataRate` /
     `formatDescriptions` 读真实分辨率 / 帧率 / 估算码率 / codec
  6. `defer` 删除临时文件
- 副作用:每次 single-variant link 多 1 次 segment 下载(几 MB,3-5 秒)。
  探测完临时文件立即删除,不会污染磁盘。
- 已知保留:macOS 13+ 的 `naturalSize` / `nominalFrameRate` 等同步访问
  API 已 deprecated,编译有 warning;新 `load(.naturalSize)` async API
  需要 `Sendable` track,目前用同步属性更简单,功能完全正确。
